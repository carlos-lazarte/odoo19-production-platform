# Contributing

## Workflow

1. Create a focused feature branch from `main`.
2. Make one coherent operational or documentation change.
3. Validate commands and configuration before committing.
4. Open a pull request with the purpose, scope and validation evidence.
5. Review the change before merging.

## Rules

- Never commit secrets or environment-specific credentials.
- Prefer parameterized examples for IP addresses, domains and credentials.
- Keep runbooks executable and explicit about prerequisites and rollback.
- Record significant architectural choices as ADRs.
- Update the changelog when a change materially affects operations.
